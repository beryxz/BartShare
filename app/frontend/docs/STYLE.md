# Style notes

## General

- Every file ends with a trailing newline.
- Prettier (`.prettierrc.yaml`) is the formatter, not a suggestion:
  80-column width, 4-space indent, no tabs, single quotes, trailing commas
  everywhere, semicolons, `arrowParens: avoid`, LF line endings. Run
  `npm run prettier` before committing (see `DEVELOPMENT.md` for commands);
  CI runs `npm run prettier:check` and fails the job on anything unformatted.

## Markdown

- Blank lines around every section header and code fence.

## React

- `'use client'` only where a hook or an event handler requires it;
  everything else stays a server component by default.

**Resetting form state on reopen.** A dialog or sheet holding form state
must reset when it reopens, whether for a different item or after an abandoned
edit. Tie the reset to the _open event_, never to prop identity: an effect keyed
on the item does not re-fire when the same item reopens. The working fixes,
chosen by who owns `open`:

- **Remount via a changing `key`**, when the parent owns `open` and the
  child holds several independent pieces of state.
  `RulesList` (`src/features/policy/components/RulesList.tsx`) bumps an
  `openToken` counter on every open and passes it as `RuleEditorSheet`'s
  `key`, forcing a fresh mount whose `useState` initialisers all run again.
- **Resync imperatively inside `onOpenChange`**, when the component owns
  its own trigger and `open`, and has one small state bag.
  `ResourceFormDialog` (`src/features/resources/components/ResourceFormDialog.tsx`)
  resets its `name`/`attrs` state inside `handleOpenChange(next)` whenever
  `next` is true, since that handler fires on every open transition regardless of
  whether the `resource` prop's reference changed.
- **Mount the dialog only while it is open**, dropping `open` as a prop
  entirely. `GroupFormDialog`
  (`src/features/network/components/GroupFormDialog.tsx`) does not own a
  trigger of its own: its callers hold the `New group` button / `Edit` menu
  item that opens it, so they can render it as
  `{creating && <GroupFormDialog ... />}` / `{editing && <GroupFormDialog ... />}`
  instead of always-mounted-plus-`open`. A closed instance does not exist, so
  there is nothing holding a stale draft to resync: the next open is a fresh
  mount, and the `useState` initialisers ARE the sync. This is usually the
  simplest, and worth reaching for first; it stops being an option the moment a
  component owns its own trigger inline (`DialogTrigger` as a child, as
  `ResourceFormDialog` does), since unmounting the dialog would unmount the
  trigger with it.

All of them tie the reset to the _open event_, not to prop identity; that is
the rule to keep, and the mechanism is whichever one fits the component.

## Conventions

- An empty attribute **pattern** is Bart's wildcard, since it matches everything;
  never render it as "no attributes"
  (`src/components/bart/AttributeList.tsx`).
- **The wildcard reading stops at patterns.** An empty _computed_ collection,
  such as `connections` or `groups` on the derived-context card, renders "none".
  It is a value, not a pattern: a party with no connections has an empty
  collection, and calling that "any" would be a lie
  (`src/features/policy/components/DerivedContextCard.tsx`).
- No attribute key is hard-coded in application logic except `username` and
  the reserved-key list; filters and facets derive from observed keys, computed
  server-side by `GET /resources/facets` / `GET /me/resources/facets` and
  fetched by `useResourceFacets`
  (`src/features/resources/hooks/useResources.ts`), with `GET /users/facets`
  doing the same over party attributes behind `useAttrVocabulary`.
- `src/components/ui/` is generated by the shadcn CLI; never hand-edit it.
- **A tone per job.** A reason a button is disabled is
  `text-verdict-deny-fg` (red); an unsaved-changes indicator is `text-warn-fg`
  (amber); explanatory text that only states a language rule, even one that
  happens to explain why a button nearby is disabled, stays
  `text-muted-foreground`. The wildcard note in `RequestBuilderPage`
  (`src/features/access/RequestBuilderPage.tsx`) is the case that stays
  muted: it explains that an empty pattern is a wildcard while the submit
  button sits disabled beside it, and the note is a language rule, not a
  disabled-reason.
